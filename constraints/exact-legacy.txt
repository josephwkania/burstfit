# Pins for EXACT reproduction of fits made with burstfit 0.1.0, your 0.6.7, numpy 1.24 and scipy 1.10.
#   pip install -c constraints/exact-legacy.txt .
#
# Python 3.11-3.12 (numpy 1.26.4 has no wheels for 3.13+). All of these have manylinux2014 (glibc 2.17)
# wheels, so they also install on systems with glibc 2.17.
#
# Pins alone are not enough. You also need:
#   1. your with the legacy spectral-kurtosis cutoff: BurstData(..., spectral_kurtosis_legacy_mad=True).
#      This needs a your with that option, which is intended for upstream thepetabyteproject/your.
#      Until a your release has it, install your from josephwkania/your, branch sk-filter-masked-mad.
#   2. BurstFit(..., legacy_spectra_window=True), for 0.1.0's spectrum window.
#   3. The same kind of machine as the reference run: AVX-512 or not (NumPy and OpenBLAS pick their
#      code paths from the CPU), and the same glibc (libm). Either changes the last bits, and
#      multi-component fits amplify that.
#
# Why these versions (bisected with 50 B0355+54 pulses, 2026-11-26/27, on an AVX2 machine and on an AVX-512 cluster):
#   - scipy 1.15.0 changed MINPACK leastsq, which the unbounded joint fit uses. scipy <= 1.14.1 is exact.
#   - numpy 2.0.0 changed its AVX-512 float64 code paths. On AVX-512 CPUs, numpy <= 1.26.4 is exact and
#     2.0-2.2 is not. Tested on Xeon Gold 6138 (AVX-512): 1.24.4, 1.25.2 and 1.26.4 gave 50/50;
#     2.0.2, 2.1.3 and 2.2.6 gave 0/50.
#   - Without AVX-512 (or with it disabled via NPY_DISABLE_CPU_FEATURES), numpy up to 2.2.6 is also
#     exact. numpy 2.3.0 changed the float32 summation order, which breaks it.
#
# Python 3.13: only exact without AVX-512 paths, with numpy==2.2.6 and scipy==1.14.1. The reference
# must also have been made without AVX-512.
#
# Speed: numpy 2.x was about 4-5x faster on AVX-512 (50 fits in ~2 min vs ~9.5 min on 38 cores).
# These pins trade that for exactness.

numpy==1.26.4 ; python_version < "3.13"
scipy==1.14.1 ; python_version < "3.13"
